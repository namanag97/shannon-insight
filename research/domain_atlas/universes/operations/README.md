# Typed operation universe

An operation is a semantically owned, typed behavior that can be required by an analytical case,
offered by a library/provider, selected by a compiler and evidenced at runtime.

```text
analytical case -> requires practice -> requires typed operations
typed operation -> lowered to library/provider capability -> emits result/evidence
```

An operation is not an untyped verb, UI action, vendor feature, job definition or complete
analytical practice. `join`, for example, is not sufficiently specified until input collections,
key/equality semantics, cardinality, null/missing rules, ordering, time, state, information loss and
failure behavior are known.

The generated registry is a hypothesis queue. It provides enumeration pressure and compiler-facing
identity, but does not claim that every name is a separate semantic owner. Deep contracts and
split/merge adjudication are required before an operation is compilable.
