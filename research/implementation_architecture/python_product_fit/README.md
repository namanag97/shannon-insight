# Python implementation fit

This package prevents a category error that had remained implicit in the repository:

```text
research/                         = open-world product/domain/contract research
src/shannon_insight/              = one implemented application-domain product
```

The Python distribution is **Shannon Codebase Insight**, an application for software-engineering
intelligence over source trees and Git history. It is not the universal data-and-analytics platform,
not a qualified implementation of every retained product, and not evidence that a research contract
has been implemented merely because similarly named Python modules exist.

## Disposition

```text
RETAIN_AS_APPLICATION_DOMAIN_REFERENCE_PRODUCT

software repository + code/tree/history observations
    -> admitted codebase facts and identities
    -> graph, temporal, statistical, semantic and tensor methods
    -> findings, signals, snapshots and evidence
    -> CLI / API / server / report experiences
```

The application is useful in three bounded ways:

1. as a real application-domain product for software-engineering intelligence;
2. as a proving ground for deterministic acquisition, fact, method, evidence and experience seams;
3. as implementation evidence only for an exact contract scope after the normal qualification
   program binds identity, build, execution, appraisal and provider/target receipts.

It must not be promoted into horizontal semantic authority. General enterprise acquisition,
warehouse/lakehouse operation, MDM, data governance, planning, arbitrary BI, industrial/clinical
sources, provider control and other horizontal products remain separate products and contracts.

## Machine-readable artifacts

- `application-boundary.json`: sovereign application boundary and non-collapse laws.
- `module-allocation-rules.json`: explicit allocation of every top-level Python module.
- `module-allocation.jsonl`: generated per-file ownership and evidence projection.
- `dependency-boundary-findings.jsonl`: observed cross-layer imports, including explicit debt.
- `implementation-crosswalk.jsonl`: evidence-only crosswalk to research coverage coordinates.
- `summary.json`: counts recomputed from the checked-out source tree.
- `manifest.json`: generated artifact hashes and source-tree digest.

The builder refuses an unknown top-level Python module. Adding a new module therefore requires an
explicit ownership decision rather than allowing architecture to grow by botanical accident.

## Validation

From the repository root:

```bash
python3 research/implementation_architecture/python_product_fit/build_module_allocation.py
python3 research/implementation_architecture/python_product_fit/validate.py --determinism
```

A passing validator proves only classification, deterministic generation, bounded ownership and
honest non-claims. It does not prove semantic ratification, implementation qualification,
portability, physical binding, vertical acceptance, build readiness or product ratification.
