- detection versus diagnosis versus proposal versus authorization versus mutation;
- policy/rule versus evaluation versus result versus effect;
- design-time/prospective versus runtime/retrospective versus reconstructed;
- event time versus recording time versus processing time versus decision time;
- deterministic law versus heuristic/statistical inference versus human judgment;
- pure semantics versus effect intent versus authorized execution versus receipt;
- generic primitive versus cross-family module versus family specialization versus local residual;
- semantic compatibility versus representation compatibility versus migration compatibility.

Actively try to falsify each boundary. Do not use vendor products, package layouts or existing names
as proof that a boundary is correct. Do not fabricate signatures to appear complete. A changed
boundary must map every old responsibility to exactly one proposed owner, without silent loss or
compatibility aliases.

The result must distinguish at least four kinds of ownership:

1. semantic owner — defines meaning, equality, laws and admissible interpretations;
2. evidence authority — supports bounded claims but does not own SAN semantics;
3. operational authority — may authorize or perform an effect;
4. implementation provider — supplies an implementation without redefining the contract.

Never collapse these roles. A standard, paper, vendor, implementation, issuer, appraiser and
operator can constrain different parts of the same record.

## Required ontology and semantic decomposition

Classify every material proposition, module, boundary and root work item on these independent
dimensions before projecting it onto libraries:

1. **semantic layer** — world phenomenon, bounded-context meaning, formal semantic object,
   contract, effect intent, authorized execution, receipt/evidence, or representation;
2. **ontological kind** — value, identity-bearing object, role, relation, event, state, process,
   rule, measure, evidence object, capability/port, or qualified homonym;
3. **formalism** — algebra/type, relation/graph, state machine, temporal model, process model,
   statistical model, evidence/argument model, constraint system, or authority protocol;
4. **time and lifecycle** — design, occurrence, observation, recording, decision, execution,
   correction, supersession, retraction, retention, deletion, or reconstruction time/state;
5. **epistemic and authority status** — asserted, observed, inferred, independently verified,
   appraised, accepted, authorized, executed, receipted, disputed, or unknown;
6. **reuse scope** — global primitive, cross-family module, family-axis module, bounded-context
   specialization, library-local residual, or external dependency;
7. **closure state** — structure known, source authority known, semantics researched,
   applicability proposed, owner unratified, contract unspecified, unimplemented, unqualified,
   blocked, or outside scope.

These dimensions are orthogonal. Do not infer authority from evidence, truth from acceptance,
execution from authorization, semantic identity from carrier equality, or implementation readiness
from researched semantics. A proposition may legitimately occupy more than one time/lifecycle or
epistemic state, but every assignment must be explicit and non-contradictory.

The live 16-axis ontology remains the mandatory coverage tensor. It is not assumed complete.
Whenever this research exposes a missing semantic axis, facet, relation or non-collapse law, emit a
typed extension candidate in the owned output rather than silently stretching an existing axis.
An extension candidate does not amend the canonical ontology and does not excuse missing coverage
against the live 16 axes.

The live decision-locus ontology is the mandatory attachment model. A family/library axis label is
only an index into research; it is not normally the final semantic bearer. For every material
proposition and contract requirement, identify the exact bearer archetype, use-site locus and
applicable coordinate questions. When a decision applies differently to two operations, claims,
relations, transitions, representations or compatibility paths in one library, split the
projection at that locus rather than inventing a library-wide default. When the live attachment
model cannot represent a decision without distortion, emit a typed bearer or coordinate extension
candidate; do not silently overload an existing term.

Construct the workload quotient in two passes:

1. group only propositions that share the same semantic question, proposed owner, formalism,
   authority requirement and closure operation;
2. split the group wherever a counterexample, local refinement, incompatible standard, lifecycle,
   authority source or public-symbol homonym changes the answer.

The quotient must be lossless and reversible: every in-scope canonical gap maps to exactly one
primary root work item, every root lists all represented gaps, and every exception maps back to the
specific library, axis and proposition that caused the split. A high reuse ratio is useful only
after this proof; it is never a target to optimize by erasing distinctions.

## Mandatory axis-first workload decomposition

Do not work through the assigned gap list sequentially. Re-index the complete assigned set by the
following independent coordinates before doing deep research:

```text
library family
  x candidate semantic owner / bounded context
  x semantic axis
  x atomic semantic question or proposition
  x lifecycle / time facet
  x epistemic / authority state
  x required closure operation
```

Use that tensor to find repeated decisions and research the highest-fanout coordinates first. A
reusable module is permitted only when every represented occurrence has the same semantic question,
owner candidate, formalism, authority requirement and closure operation. Split immediately when a
library changes the carrier, equality, lifecycle, authority, refusal, temporal, evidence,
compatibility or conformance answer. Equal vocabulary, neighboring concepts, shared sources and
similar implementation shapes are not sufficient grounds for reuse.

For each axis, produce all three results rather than a single generic essay:

1. a bounded family/module proposition with primary evidence, authority limit and negative twin;
2. an explicit applicability decision for every affected library occurrence;
3. a typed residual for every exception, missing owner decision, missing exact contract or missing
   conformance oracle.

Treat the 16-axis tensor as the exhaustive coverage obligation for the current ontology, not as a
claim that all 16 axes apply to every library. `NOT_APPLICABLE` must be explicit and justified;
silence is an error. If a material question cannot be expressed by the live axes, emit an
`EXTENSION_CANDIDATE`, preserve the affected cells and gaps, and keep them unresolved. Never stretch
an existing axis merely to make coverage appear complete.

Maintain two counts throughout the work:

- **coverage count** — exact library occurrences and canonical gaps accounted for;
- **decision count** — distinct semantic propositions or owner decisions that must be researched
  and ratified.

Compression is successful only when the first count remains exact while the second count becomes
smaller for defensible semantic reasons. Neither count is a closure count. Evidence research may
move a root item to `RESEARCHED_UNRATIFIED`; it must not close canonical gaps, assign canonical
owners, invent exact APIs or qualify providers.

### Semantic quotient proof and acceleration law

The purpose of the quotient is to avoid treating hundreds of gap occurrences as hundreds of
independent research problems. It is not permission to replace them with broad prose. Derive an
explicit semantic decision signature for every in-scope gap occurrence before deciding whether it
can share a root work item:

```text
semantic decision signature =
    bounded-context owner candidate
  x owned atomic question
  x semantic axis and refined coordinate question
  x smallest bearer/use-site locus
  x ontological kind and formalism
  x lifecycle/time facet
  x epistemic and authority requirement
  x required closure operation
  x evidence-authority class
  x conformance-oracle kind
```

Two occurrences may share a primary root work item only when these components are equal or when a
researched, source-backed parameterization proves that their difference is an explicit input to
the same decision kernel. Lexical similarity, a shared family, a shared source, an equal output
shape, neighboring implementation packages or a desire for a smaller task count never establishes
equivalence.

For every proposed multi-occurrence root, attempt at least these split tests:

- can the two occurrences have different semantic owners?
- can one be pure and the other effectful or authority-bearing?
- can identity, equality, time, lifecycle, refusal precedence or compatibility differ?
- can a standard be authoritative for one occurrence but merely informative for another?
- can one occurrence require a different negative twin or conformance oracle?
- can one be `NOT_APPLICABLE` on a refined coordinate that applies to the other?
- can a counterexample satisfy one proposed contract while violating the other?

If any answer is yes and the difference is not an explicit parameter with its own law and oracle,
split the root. Record the counterexample and the exact occurrence that forced the split. Conversely,
do not create singleton work merely because libraries have different names when the signature and
all split tests establish the same decision kernel.

Work in ontology-first waves rather than library order:

```text
Wave 0  exact inventory, snapshot and occurrence-to-gap graph
Wave 1  bounded contexts, semantic owners, homonyms and non-collapse laws
Wave 2  highest-fanout atomic questions and reusable formal decision kernels
Wave 3  complete library x axis x locus applicability projection
Wave 4  counterexample-driven splits, local residuals and evidence vacancies
Wave 5  exact contract requirements, laws, refusals and conformance oracles
Wave 6  downstream blast radius, merge proposals and deterministic validation
```

Complete each wave across the entire assigned universe before polishing low-fanout local essays.
Within a wave, prioritize a root by dependency centrality, fanout and risk of invalidating downstream
boundaries—not by ease, source popularity or numeric gap order. A high-fanout question with weak
evidence remains an explicit vacancy; it must not be mechanically propagated as a researched
answer.

Apply an annealing loop at the quotient level:

1. **compress** occurrences with provisionally equal semantic signatures;
2. **falsify** each multi-occurrence group using negative twins, homonyms and boundary cases;
3. **split** wherever one law, owner, authority, lifecycle, closure operation or oracle no longer
   fits;
4. **project** the surviving kernel back onto every occurrence without defaults;
5. **measure losslessness** by exact reverse mapping and exception preservation;
6. repeat only while a new split, merge, owner correction or dependency change is found.

The annealing stopping condition is not “no more material found on the internet.” Stop when another
iteration produces no change to the candidate ontology, semantic signatures, root partition,
exception set, dependency graph, applicability tensor or evidence-vacancy set, and all remaining
uncertainty is typed and routed. Record the final iteration count and change counts in the coverage
report. This is convergence of the captured research model, not proof of global truth or canonical
closure.

## Research standard

Search the internet broadly. Prefer normative standards, original peer-reviewed papers, official
protocol/project specifications, reference implementations and conformance suites. Use secondary
sources only for discovery when primary material exists. Record exact title, issuer/authors,
edition/version/date, stable URI/DOI, bounded supported claims, unsupported claims, limitations,
access date and confidence. An LLM output is never evidence.

Preserve at least these distinctions and find further domain-specific ones:

- data / metadata;
- event / assertion / evidence / proof / truth / acceptance / authorization / execution;
- provenance statement / issuer-scoped assertion / named bundle / interchange encoding;
- observation / inference;
- design lineage / runtime lineage;
- derivation / causation;
- integrity / authenticity / correctness;
- evidence / appraisal policy / appraisal result / relying-party decision;
- quality dimension / metric / measurement / assertion / judgment;
- detection / diagnosis / correction proposal / authorized mutation;
- match candidate / match confidence / approved match / identity resolution;
- validation completion / conformance / publication eligibility;
- sampling evidence / population claim;
- missing evidence / negative evidence / incomplete coverage;
- retraction / deletion / supersession;
- technical retention / retention authority.

For lineage/provenance/evidence, explicitly test whether distinct semantics are needed for entity,
activity and agent provenance; derivation, generation, use, attribution, association and delegation;
prospective versus retrospective lineage; logical versus physical lineage; source, transform and
observation time; asserted versus observed versus independently verified facts; bundle/named-graph
identity; redaction, disclosure and evidence decay; correction, supersession and retraction; and

For quality/reconciliation, explicitly test whether distinct semantics are needed for constraint,

materiality, sampling frame, population claim, control total, settlement/finality and reopened
case. Do not convert domain-specific correctness into a universal numeric quality score.

## Execution strategy

Use the dependency order below. Earlier work may invalidate or collapse later work:

```text
source structure
      ↓
source authority and bounded claims
      ↓
shared symbol / homonym adjudication
      ↓
family × semantic-axis evidence modules
      ↓
clustered per-library applicability decisions
      ↓
library-local residual contract requirements
```

Start by clustering assigned libraries by semantic owner, axis, candidate facets and repeated
public vocabulary. Research the highest-fanout clusters first. Actively search for counterexamples
and incompatible definitions. Do not unify equal names, equal spellings or equal JSON shapes
without a semantic-owner decision. Do not copy a family-level conclusion into every library;
reference the module and record only the member's applicability, refinement or exception.

Use this bounded work loop:

```text
inventory and input snapshot
        ↓
candidate ontology and repeated decision points
        ↓
highest-fanout module research + counterexample search
        ↓
applicability projection across all assigned libraries
        ↓
local residual and changed-boundary research
        ↓
gap dependency graph + deterministic validation
        ↓
repeat only where validation or falsification exposes a material defect
```

Research breadth is not completion. Stop expanding a proposition when authoritative sources and
counterexamples establish its bounded claim and remaining uncertainty is recorded as a typed gap.
Continue when the proposition still changes ownership, non-collapse laws, applicability or public
contract requirements.

Do not plan or close the canonical queue one library or one gap at a time. Construct a quotient of
the workload by repeated semantic question, owner candidate, semantic axis, decision dependency,
public-symbol collision and required authority. A root work item may represent many downstream
library gaps only when it contains an exact, reversible mapping to every represented input gap and
records exceptions. Research the highest-fanout root decisions first. Never use clustering to erase
a local residual, counterexample or independent owner decision.

For this assignment, the in-scope canonical gap set is the exact union of `closure_refs` in
`research-batches.jsonl` records whose `research_family` is `lineage_provenance_evidence` or
`quality_reconciliation`. Do not absorb closure refs from other families merely because their
concepts are neighboring or their names collide; record those as external dependencies.

For each research proposition, separate:

1. the atomic claim;
2. its primary evidence and bounded supporting passage/section;
3. the inference made by this research lane;
4. counterevidence or incompatible definitions checked;
5. scope and invalidators;
6. affected modules, libraries, axes and root gaps;
7. whether the record is researched, mechanically projected or unresolved.

A source attached somewhere to a module is not enough. The validator must be able to trace every
material claim to bounded evidence or to an explicit evidence vacancy. Do not impose an arbitrary
source count: evidence quality, authority fit, independence and counterexample coverage matter more
than volume. Vendor documentation may prove vendor behavior; it does not by itself prove a global
semantic boundary.

## Completion condition

The assignment is complete only when all assigned input library refs are accounted for, the
highest-fanout reusable propositions have bounded primary evidence and counterexamples, every
projection or residual is explicit, the complete library x axis tensor is decided without silent
defaults, the candidate semantic ontology is explicit, every material claim has claim-level
provenance, every in-scope canonical gap is represented by
exactly one primary root work item, every unresolved issue is represented in the gap graph, merge
candidates are machine-readable, the concise DAG is current and the validator passes without
weakening its laws. This means
the research lane is structurally complete for its stated input snapshot; it does **not** mean that
the proposed semantics are ratified, implemented, qualified or globally complete.

Every assigned library and canonical gap must also have a lossless downstream-impact disposition:
all declared P5-P8 and library/product/composition edges affected by the research are traced, or
the snapshot explicitly records that it contains no declared downstream consumer. This is blast-
radius completeness for the captured graph, not proof that the enterprise ontology has enumerated
every possible consumer.

Structural completeness additionally requires that every live semantic axis, semantic-axis
campaign, coordinate ontology, targeted-evidence adjudication, domain-formalism slice and
semantic-research or analytical-formalism frontier has an explicit intake disposition, that the
assigned library x axis tensor has no silent cells, that material decisions have explicit
bearer/coordinate projections or typed vacancies, and that every compression from canonical gaps
to root decisions is lossless and reversible. Do not claim completion merely because all files
exist, all gaps have a root ID, all members have a mechanical route or the quotient ratio is high.

When finished, return the output directory path, exact input snapshot digest, validator
command/result, artifact counts and a concise factual summary of corrections, blockers and merge
candidates. Do not merge anything into the canonical corpus.
