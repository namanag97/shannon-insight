# Data preparation and profiling semantic slice

This deterministic, evidence-backed and unratified research slice decomposes the open
`formalism.data_preparation_profiling` frontier cluster. It tests the current product and library
graph without treating existing names as conclusions.

## Boundary result

```text
source access / ingestion                         imported
        │
        ▼
admitted immutable data cut
        │ parse + infer + profile                 hypotheses, not declarations
        ▼
interactive preparation project
        │ facet / select / transform / reshape / join / repair-propose
        ▼
editioned recipe + preview + replay + diff
        │
        ▼
prepared-output edition + publication handoff
        │
        ├─ deployed recurring transform build    different product
        ├─ quality acceptance/certification       different authority
        └─ downstream analytical use              consumer
```

- Retain `product.self_service_data_preparation`, but narrow it to immutable data-cut admission,
  interactive project/view state, typed recipe authoring and history, preview/replay/diff, repair
  acceptance, and prepared-output publication handoff.
- Treat profiling as a reusable evidence capability consumed by preparation, catalog and Data
  Quality—not as an independent product or declaration authority.
- Keep inferred schema separate from declared schema, profile observations separate from quality
  requirements and verdicts, and preview separate from full-data execution evidence.
- An accepted interactive recipe is only unqualified input to Batch Transform Build; deployment,
  schedules, resources, operations and production qualification remain there.
- Source mutation, carrier codecs, generic query execution, storage/runtime effects and downstream
  business effects remain outside this product boundary.
