# Toolkit family specifications

Normative family specifications live with their owning toolkit family. The
repository-level `docs/` directory holds platform-wide constitutions,
architecture, and methods; it is not the home of family-local contracts.

All reviews use the derived
[R01–R44 pure-library checklist](../docs/architecture/domain-libraries/pure-library-rules.md#0-canonical-review-list).
The single normative rules source remains
[`docs/PURE-LIBRARY-CONSTITUTION.html`](../docs/PURE-LIBRARY-CONSTITUTION.html).
Composition/admission gates: [`docs/COMPOSABLE-PRODUCT-KERNEL.html`](../docs/COMPOSABLE-PRODUCT-KERNEL.html)
(§0d gates C01–C12, §22 boundary/axis tests, §22.2 capability census).
Program status: [program dashboard](../docs/PROGRAM.html).

## Source-authority ruling

The old SAN toolkit is deprecated evidence. This includes
`toolkit/factory/**`, `toolkit/foundation/**`, old chassis/kernel/platform
families, and their local contracts, registries, envelopes, compilers and IRs.
They are not suppliers for the families indexed here. In particular, shared
family descriptors and composition machinery MUST NOT be added to or imported
from old Factory. Existing imports from an indexed candidate into deprecated
code are migration defects. Replacement cross-domain machinery requires its
own ratified greenfield platform boundary and proof.

The `toolkit/` path prefix does not confer authority. This ledger indexes
greenfield canonical candidates; each remains a candidate until its exact
implementation passes the Constitution and is promoted by a convergence
record.

## Implementation-scope ruling

Every HTML specification indexed below is the complete implementation target
for its family. An explicit gap ledger is part of that target: it defines an
honest unsupported case and its reopening rule; it does not authorize a narrow
implementation of the remaining sections. A locally green crate or vertical is
only evidence for the exact laws it exercises. No family is complete until its
entire specified native API, decision surface, evolution surface, proof surface,
and composition surface have Rust evidence.

### Completion states are not interchangeable

Workflow completion, document existence and a green structural checker are not
ratification.  Every family advances through the following evidence states in
order; a report MUST name the highest state actually evidenced and MUST NOT use
the unqualified word “complete” for any earlier state:

| State | Evidence required |
|---|---|
| **DRAFTED** | One owned HTML source states the sovereign question, boundary, ubiquitous language, native shapes and operations, exhaustive decision/refusal space, evolution model, laws, proof obligations and honest gaps. |
| **STRUCTURAL** | The source passes `scripts/verify_family_specs.py`; this proves document shape only. |
| **SOURCE_COMPLETE** | The strict contract-source audit finds one exact owner `ContractHeader` for each offered seam and one exact consumer `ContractEdgeSpec` for each imported seam, or an explicit empty source. |
| **REVIEWED** | A genuinely independent reviewer has checked semantic ownership, decision saturation, operation/observer/refusal totality, reciprocal seams, standards claims and every PASS disposition against repository evidence. `PENDING` is not review. |
| **IMPLEMENTED** | Greenfield idiomatic Rust realizes every declared public item and decision; direct Rust construction and admitted card construction converge to the same semantic value; no deprecated supplier edge remains. |
| **CERTIFIED** | Executable law, conformance, negative/deviation, mutation, compatibility and resource evidence covers the whole declared surface at the claimed assurance level. |
| **RATIFIED** | A convergence record pins the exact source, Rust artifacts, dependency graph and proof digests and promotes that edition as canonical. |

The two Claude workflow records from 2026-08-07 are orchestration logs, not
evidence states.  Their top-level `completed` status means the workflow process
ended.  It does not override dropped author jobs, missing independent reviews,
a null closing job, red global gates or absent Rust realization.

## Cross-family seam ground census

Run `python3 scripts/extract_family_seams.py` to regenerate
`target/architecture/family-seam-catalog.json`. The report inventories the
human seam matrices and derives an incidence map only for visibly editioned
contract identities. It is not a linker and it does not infer compatibility
from similar Rust type names.

The generated report records the current number of seam tables, rows, visibly
editioned identities, repeated identities, uneditioned rows and the exact
source-set digest. Mutable counts are not repeated here because repair passes
change them continuously. Some one-sided identities legitimately target an
owner whose HTML specification is still missing, and some rows describe local
payloads rather than contracts. Nevertheless, the result disproves any claim
that the current family DAG or reciprocal contract ledger is already frozen.
Semantic acceptance requires every actual cross-family edge to resolve to one
exact `ContractEdgeSpec` identity, edition, mode, scope, guarantees,
cardinality, phase, obligations, witness and refusal on both sides—or to remain
an explicit owned gap. Table presence and name similarity are insufficient.

Run `python3 scripts/audit_family_contract_sources.py` to regenerate
`target/architecture/family-contract-source-audit.json`. Unlike the seam
census, this audit counts only machine-authorable `ContractHeader` and
`ContractEdgeSpec` source records; it never promotes a human matrix into
compiler input. The current strict audit remains red: the shelf overwhelmingly
contains seam projections without their owner-authored definitions and
consumer-authored edge records. That is now an explicit specification blocker,
not work deferred to Rust implementation.

## Assembly ruling

A named capability is not automatically a crate or a sovereign family. The
current specifications classify as follows:

The R01 architectural class remains the family's real class; dependency tiers
do not replace it. **Root substrate** has one strict meaning: a native semantic
core has no incoming edge from another SAN semantic family and carries no
institutional authority, lifecycle, currentness or policy. It may use
`core`/`alloc`/`std`, audited subordinate OSS mechanics and same-family
derive/data modules. Shared metamodel projection belongs in a separable
contribution module; importing it from the native core is a migration defect.

**Foundation closure** is broader: it is the acyclic transitive closure built
over root substrate. Its members may depend downward on root/foundation
contracts, but never upward on application, institutional, runtime, provider or
deprecated toolkit authority. A concern may be foundational without being root
substrate. Bitemporality is the canonical example: it is widely reusable but
necessarily consumes Instant plus Truth/Journal record-position contracts, so
classifying it as zero-dependency substrate would erase its semantics.

| Architectural class / dependency tier | Current specifications |
|---|---|
| Foundation algebra · S0 root representation substrate | Canonical Form, Encoding and Text core. Encoding is now self-contained; Text's shared-metadata imports must still be isolated from native semantics before root status is proven. |
| Foundation algebra · S0 root scalar substrate | Magnitude. It owns exact decimal/rational/quantization semantics. Fixed Time Span is not a second scalar root: SEM-010 seals SEM-007 Quantity over SEM-006 time-dimension units. |
| Foundation algebra · F1 derived values | Digest, Unit, Elapsed, Quantity, Rate, Instant and Path have target specifications. Their reciprocal contracts and implementation evidence remain unratified; a source file closes the specification hole, not composition/proof. |
| Relational semantic foundation · F2 | Causality and Bitemporality. Both are reusable semantic families above Instant/Identifier; Bitemporality additionally requires Truth/Journal record-position authority. Neither is root substrate. |
| Foundation algebra · P2 institutional values | Money, Calendar, Recurrence, Expiry. These remain reusable pure libraries, but currency, jurisdiction, civil-time and policy meaning keeps them above the substrate. |
| Sovereign semantic family | Identifier, Namespace, Causality, Bitemporality, Locator, Path, Reference, Designation, Identity, Tenancy, Recognition, AuthN, Federation, Delegation, Correspondence, Vocabulary, Recurrence, Expiry, Journal, Evidence, Provenance, Derivation, Adjudication (candidates; structural/semantic review incomplete) |
| Composed application/domain pack | Organization |
| Classification unresolved | Authorization, Commitment, Decision, Entitlement, Holding, Integration, Ledger, Model, Process, Query-Contract, Work (newly indexed review candidates; their titles do not establish architectural class or ratification) |

The table intentionally exposes unresolved duplicate classifications for Path,
Recurrence and Expiry in the older shelf.  Their family specifications, not
this ledger, must close those classifications before ratification.  No folder
name or prior row silently resolves the conflict.

`toolkit/measure` is not the missing Unit owner. Its working notes define a
business-measure family (grain, additivity and aggregation meaning) at a higher
tier. Unit owns dimension/unit definitions and exact conversion passports;
Quantity consumes those passports; Measure consumes admitted Quantity values.

Every family owns its native values, invariants, operations, refusals,
decision semantics, imports, exports, evolution rules, and laws. A family-local
plan, cards module, state machine, port, testkit, or declaration grammar exists
only when an independently named consumer or law requires it. Families do not
each own a compiler, linker, loader, provider framework, or runtime. Those are
shared platform mechanisms over explicit `ContextSpec` contributions, compiled
`ContextDescriptor` values and typed contracts.
