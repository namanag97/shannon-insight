# Analytical-operation product adjudication

This deterministic bundle promotes five evidence-backed inventory hypotheses into strong product
candidates without ratifying them:

1. Self-Service Data Preparation Workbench
2. Annotation and Ground-Truth Operations
3. Document Processing and Review Operations
4. Visual Inspection Operations
5. Signal Condition Monitoring and Diagnostics

Each product has a full strategic/tactical DDD dossier, a total state vocabulary, paired commands
and events, invariants, refusals, context-map translations, time and concurrency models, policies,
sagas, read models and non-functional laws. Sixty semantic library contracts expose exact types,
operations, decision points, invariants, refusals and effect boundaries.

Compiler binding is fail-closed. Existing registry contracts are referenced only where their
meaning is reusable. Missing exact contracts produce blocking binding gaps. All observed providers
remain unqualified; no portability or implementation count is fabricated.

The shared measurement pass closes four initial placeholders without creating a vague sensor
utility. Condition asset/channel binding maps to the observation-binding compiler; visual
inspection acquisition maps to observation binding plus the acquisition-profile compiler; and both
condition and inspection calibration map to the same calibration-record compiler and pure
evaluator. Product-specific programme, recipe, analytical method, judgment and effect authority
remain local. The shared contracts live in
`research/domain_atlas/universes/measurement_acquisition_calibration/`.

The governed executable-recipe pass closes inspection recipe governance and preparation recipe
replay/history without merging the products. Both reuse a typed recipe-definition compiler;
preparation additionally binds replay planning/evaluation and branch-preserving edit history;
inspection additionally binds lifecycle validation and target-preparation request/receipt
reconciliation. Step meaning, product review, release authority, physical scheduling and outcome
acceptance remain separately owned.

Predictive, probabilistic, generative and agent mechanisms are optional typed method/proposal
bindings. They are not product names or semantic owners. Removing them preserves the complete
deterministic lifecycle. Automation does not replace domain vocabulary, boundary adjudication,
invariants, state machines, evidence, conformance or acceptance work.
