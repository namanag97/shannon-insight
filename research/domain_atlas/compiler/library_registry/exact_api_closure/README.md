# Exact-API closure program

This deterministic queue covers every live `exact_api_contract_missing` gap in the governed library
registry. It prioritizes work by retained-product use, unrelated-vertical reuse, dependency
centrality, kernel use and effect risk. Priority controls work order only; every item has the same
non-negotiable closure contract.

An item closes only when its semantic owner publishes exact public types, traits, typed operations,
refusals, effects, configuration decisions, laws, compatibility rules and conformance oracles in the
source universe, and regeneration removes the central gap. Generated placeholders, vendor SDKs,
marketing surfaces and model/agent proposals are not API authority.

```bash
python3 research/domain_atlas/compiler/library_registry/exact_api_closure/build_program.py
python3 research/domain_atlas/compiler/library_registry/exact_api_closure/validate.py
```

`closure-queue.jsonl` is the exact per-library work queue. `research-batches.jsonl` assigns every
gap exactly once to a semantic research family and one of four work lanes: boundary-first,
semantic-contract, algorithm/conformance, or effect/runtime/provider. Each batch carries its primary
evidence program, products, verticals, owners and closure law. High-leverage families also carry
bounded primary-source discovery seeds. A discovery seed is not adopted semantic authority: its
claims, edition, conflicts, applicability and counterexamples still require owner adjudication.
`summary.json` and `manifest.json`
provide counts and deterministic digests. API closure does not establish implementation,
qualification, portability, product readiness or vertical acceptance.

`../contract_generation/` consumes this complete queue and turns it into archetype obligations,
family constitutions, boundary-falsification clusters and governed batch work packages. It is the
scalable execution layer; its proposals are deliberately incapable of closing this queue until a
named semantic owner publishes an exact source-universe contract.
