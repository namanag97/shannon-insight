# Schema and Data-Contract Governance

This universe closes thirteen compiler-critical semantic boundaries without collapsing structural schema governance into negotiated data-contract governance.

```text
Schema Registry                         Data Contract Registry
├── subject identity                    ├── contract identity
├── artifact profile                    ├── parties, purposes and roles
├── immutable version registry          ├── data/schema bindings
├── directional compatibility           ├── quality/service obligations
├── exact reference closure             ├── compatibility and acceptance
└── consumer-aware migration            ├── change/breach cases
                                        └── deprecation and exit
```

Critical laws:

```text
parse validity != compatibility != migration safety
wire compatibility != source compatibility != business substitutability
schema subject != topic/table/dataset
contract document != contract identity != immutable edition != registry occurrence
contract validity != acceptance != observed attainment
threshold violation != adjudicated breach != remedy effect
deprecation != sunset != termination != completed exit
```

Registration, publication, acceptance, case handling and termination use pure effect intents and receipts. No semantic library performs ambient I/O or grants authority. All reference offers remain unqualified, non-portable and non-selectable.
