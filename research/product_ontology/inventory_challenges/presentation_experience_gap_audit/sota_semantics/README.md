# SOTA presentation semantics extension

Status: **evidence-backed research candidate, not ratified**.

This package extends the parent `presentation_experience_gap_audit` with the open-world evidence and machine-readable semantic layer needed to answer a different question: what presentation capabilities, question intents, visual grammars, specialist analytical experiences, interactions and acceptance obligations recur across independently adopted SOTA products and unrelated industries?

It does not replace or re-own the parent product-boundary, semantic-owner or exact-contract adjudications. `canonical-bridges.jsonl` maps every candidate seam back to an existing parent library hypothesis where one exists and otherwise leaves an explicit parent-adjudication requirement.

The compilation model is:

```text
QuestionIntent
  -> TypedAnalyticalResult
  -> deterministic semantic + fitness constraints
  -> PresentationPlan
  -> generic visual grammar | typed specialist experience
  -> interaction + artifact lifecycle
  -> accessibility + uncertainty + missingness + provenance + policy + resource gates
  -> renderer | export | embed
```

Provider names are evidence identifiers only. They are never semantic compiler dispatch keys.

Current research projection covers 88 official/primary sources, 21 benchmark archetypes, 68 products/projects, 456 provider feature observations, 50 typed result kinds, 140 question intents, 214 normalized visual patterns, 21 specialist experience families, 50 interaction contracts, 63 candidate library seams, 42 vertical acceptance cases across 30 industries, 12 saturation trials and 70 adversarial/non-collapse tests.

Late pressure tests retain typed specialist roots for medical imaging, network operations, security investigation and construction/BIM. Supply-chain control towers are modeled as compositions of planning, decision-support, exception, network/geospatial and dashboard semantics rather than as a new root solely because vendors package them together.

Research saturation is evidence for the current root-family frontier, not proof that future products cannot introduce new semantics. Ratification, implementation qualification, provider qualification and executed vertical acceptance remain downstream gates.

Rebuild and validate from the repository root:

```bash
python3 research/product_ontology/inventory_challenges/presentation_experience_gap_audit/sota_semantics/build.py
python3 research/product_ontology/inventory_challenges/presentation_experience_gap_audit/sota_semantics/validate.py
```
